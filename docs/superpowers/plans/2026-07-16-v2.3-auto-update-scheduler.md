# v2.3 Auto Update Scheduler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add persisted per-novel auto-update policies, a local scheduler, diagnostics history, and UI controls without changing crawler semantics.

**Architecture:** Persist update policy columns on `novels` and scheduler run history in `novel_update_diagnostics`. A scheduler service periodically queries due novels, skips novels with active tasks, invokes `UpdateNovelUseCase`, records outcomes, and computes retry backoff. Expose scheduler/policy/history endpoints and render policy plus diagnostics in Novel Detail and scheduler status in Settings.

**Tech Stack:** Node.js 22+, TypeScript, Express, node:sqlite, React, TanStack Query, existing FSD/shared UI.

## Global Constraints

- Keep SQLite migration backward compatible.
- Do not add runtime dependencies.
- Scheduler must work on Windows, Linux, and Termux.
- Do not create duplicate crawl tasks for a novel with an active task.
- Existing manual update behavior remains unchanged.
